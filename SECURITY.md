# Security Policy

Security reports must be submitted privately. Do not open a public issue for a
suspected vulnerability.

## Reporting

The public repository owner must enable GitHub private vulnerability reporting
before launch. After it is enabled, use the repository's **Security** tab and
select **Report a vulnerability**.

No 4.js security email address has been configured in this source snapshot.
Repository maintainers must add and test a monitored private contact before
publishing the project.

Include:

- A description of the vulnerability and its impact
- A minimal reproduction or affected files and versions
- Any known mitigations
- Whether the issue is already public

Maintainers should acknowledge a complete report promptly, provide status
updates while a fix is prepared, and coordinate disclosure with the reporter.
